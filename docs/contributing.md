# Contributing

## Branch naming

Use clear and consistent branch names for WorkHub ticket work:

- `feature/WH-123-add-project-crud`
- `bugfix/WH-456-fix-api-issue`
- `chore/WH-789-update-docs`

## Pull request process

- Create a branch from `main`.
- Push changes and open a PR against `main`.
- Include a summary of what changed and why.
- Add links to the related WorkHub ticket.
- Ensure CI passes before requesting review.

## Code review expectations

- Keep changes focused and easy to review.
- Add or update tests for new behavior.
- Prefer readable, maintainable code.
- Document architecture decisions when needed.
- Address review comments by pushing follow-up commits.
